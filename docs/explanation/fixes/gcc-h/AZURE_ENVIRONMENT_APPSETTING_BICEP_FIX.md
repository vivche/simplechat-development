# AZURE ENVIRONMENT APP SETTING BICEP FIX

## Overview
This fix updates App Service configuration generated by Bicep to publish the correct environment variable key required by runtime cloud selection logic.

Related issue: **#763**

Fixed in version: **0.238.025**
Related config version: `application/single_app/config.py` (`VERSION = "0.238.025"`)

## Issue Description
After deployment, App Service did not contain `AZURE_ENVIRONMENT`. The app then defaulted to `public` cloud behavior in runtime config, which caused government cloud deployments to call public management endpoints and fail model fetch operations with subscription lookup errors.

## Root Cause Analysis
The App Service module set `AZURE_ENDPOINT` instead of `AZURE_ENVIRONMENT`.

Runtime code reads:
- `AZURE_ENVIRONMENT = os.getenv("AZURE_ENVIRONMENT", "public")`

Because the expected key was missing, the application fell back to `public`.

## Technical Details
### Files Modified
- `deployers/bicep/modules/appService.bicep`
- `deployers/bicep/main.json`

### Code Changes Summary
1. Renamed app setting key in Bicep module:
   - `AZURE_ENDPOINT` -> `AZURE_ENVIRONMENT`
2. Kept generated ARM template in sync:
   - Updated corresponding key in `main.json` to `AZURE_ENVIRONMENT`.

## Validation
### Before
- App Service app settings did not include `AZURE_ENVIRONMENT`.
- Gov deployment runtime defaulted to `public` cloud behavior.

### After
- App Service receives `AZURE_ENVIRONMENT` with value:
  - `usgovernment` for AzureUSGovernment
  - `public` otherwise
- Runtime cloud-specific endpoints resolve correctly.

## Post-Deployment Check
1. Open App Service -> Configuration -> Application settings.
2. Verify `AZURE_ENVIRONMENT` exists.
3. Confirm value is lowercase `usgovernment` in GCC-H.
4. Restart App Service and retest model fetch/admin operations.
